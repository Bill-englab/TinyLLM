## `apps/quantize_bnb.py`

### 关键函数

- `build_bnb_int8_config()` → 返回 INT8 配置(LLM.int8() 混合精度)
- `build_bnb_nf4_config()` → 返回 NF4 4-bit 配置(双重量化 + FP16 计算 dtype)
- `load_model(name, quant_config)` → 加载模型,返回 `(model, tokenizer, load_time)`
- `run_inference(model, tokenizer, prompts)` → 跑批量推理,统计 tokens/s
- `release_model(model)` → 彻底释放(`gc + torch.cuda.empty_cache`)
- `write_log(results)` → 把对比表和输出写到 markdown

### 设计要点
- **关闭采样**(`do_sample=False`):保证三种方案输出可比
- **每次加载前释放上一个模型**:避免显存累积
- **记录 PyTorch peak memory**:用 `torch.cuda.max_memory_allocated` 拿到峰值,比 `nvidia-smi` 更准

## `experiments/gptq_quantize.py`

### 关键流程
```
load FP16 → run baseline prompts → release FP16
   ↓
GPTQConfig(bits=4, group_size=128, dataset=CALIB_TEXTS)
   ↓
AutoModelForCausalLM.from_pretrained(quantization_config=...)
   ↓ [内部:校准 → 逐层量化 → packing]
save_pretrained(OUTPUT_DIR)
   ↓
load saved GPTQ → run prompts → compare with FP16
```

### 校准数据设计
`CALIBRATION_TEXTS` 内置 130 条文本(无网络依赖):
- 英文段落(20):通用知识、科学、技术
- 中文段落(20):语言、知识、文化
- 代码片段(10):Python、SQL、bash、docker
- 数学(5)、对话(10)
- 全部 ×2 = 130 条

设计原则:**贴近真实推理场景的分布**。

### 输出对比
固定 3 个 prompt,FP16 跟 GPTQ 各跑一遍,人工对比。注意:**1B 模型本身能力有限**,差异更多来自模型本身而非量化。

## `benchmarks/bench_throughput.py`

### 关键指标
- **throughput (tok/s)**:`total_new_tokens / wall_time`
- **latency (s/req)**:`wall_time / batch_size`
- **TTFT (Time To First Token)**:生成 1 个 token 的耗时,反映 prefill 阶段性能

### 关键函数
- `bench_batch(model, tokenizer, prompts, max_new)`:
  - 先跑 1 个 prompt 1 个 token 测 TTFT
  - 再跑完整 batch 测吞吐
  - 注意 token 计数要截断到 EOS,避免 padding 干扰

### Batch size 测试
默认 `[1, 4, 8]`,可命令行覆盖:
```bash
--batch-sizes 1 2 4 8 16
```

## `benchmarks/bench_memory.py`

### 三个维度的显存
- **磁盘 (GB)**:`du -sh model_dir`,反映模型文件大小
- **稳态显存 (GB)**:模型加载后、推理前的 GPU 占用
- **峰值显存 (GB)**:`torch.cuda.max_memory_allocated()`,推理过程中的 PyTorch 分配峰值

### 注意
- `nvidia-smi` 显示的显存 ≥ PyTorch peak,因为 PyTorch 预留 caching allocator
- 比较方案时,优先看 PyTorch peak(更精确反映模型的真实需求)

## `apps/serve_quantized_vllm.py`

### 三种模式
- `chat`:交互式命令行对话
- `bench`:固定 5 个 prompt 测速
- `api`:OpenAI 兼容 HTTP 服务

### 加载逻辑
```python
model = AutoModelForCausalLM.from_pretrained(
    model_path,
    device_map="auto",
    trust_remote_code=True,
)
```
**不需要显式传 quantization_config**:GPTQ 模型的 `config.json` 里有 `quantization_config` 字段,from_pretrained 自动识别并应用。

### API 兼容性
- `POST /v1/chat/completions`:OpenAI chat 格式
- `GET /v1/models`:列出模型
- `GET /health`:健康检查

可以直接用 `openai` Python 库或任何 OpenAI 客户端访问。

## `scripts/setup_env.sh`

### 关键步骤
1. 把 `~/envs` 加入 `envs_dirs`(绕开 NTFS)
2. 把 `~/conda-pkgs` 加入 `pkgs_dirs`
3. 创建 `inference_opt` (Python 3.10)

5. 装 PyTorch + 量化栈
6. 跑 `check_env.py` 验证

脚本第一次运行如果失败,**不要简单重跑**,可能留下半成品环境。先清理:

```bash
rm -rf ~/envs/inference_opt
conda env remove -n inference_opt  # 双重保险
```

## 扩展建议

### 想加入新的量化方法
1. 在 `apps/` 或 `experiments/` 新建脚本
2. 复用 `benchmarks/` 的基准(它们接受任意模型路径)
3. 在 `使用指南.md` 增加使用说明

### 想换模型
- 修改脚本里的 `MODEL_PATH` 或设置环境变量 `LLM_MODEL_PATH`
- 注意大模型可能 OOM,需要降 `gpu_memory_utilization`

### 想做更严格的精度评估
- 加 MMLU / CMMLU 评测(需 pip install lm-eval)
- 加 BLEU / ROUGE(对生成式任务)
- 跟人工评分对比

### 想做端到端服务部署
- 用 `serve_quantized_vllm.py api` 起服务
- 或者用 vLLM 直接跑(`pip install vllm` 后看该文件末尾附录)
- 配合 nginx 反向代理、systemd 自启动
