# 使用指南:阶段 2 量化实验

## 1. 环境激活

每次开新终端先激活:
```bash
conda activate inference_opt
```

环境路径在 WSL2 原生 ext4(`/home/<user>/envs/inference_opt/`),不在 NTFS。

## 2. 实验执行顺序

按依赖关系,推荐顺序:

```
[概念] docs/量化基础概念.md
   ↓
[实验 1] apps/quantize_bnb.py       ← 动态量化入门,5 分钟
   ↓
[实验 2] experiments/gptq_quantize.py ← GPTQ 静态量化,15-30 分钟
   ↓
[实验 5] scripts/run_all_benchmarks.sh ← 三维基准对比,10-15 分钟
   ↓
[实验 6] apps/serve_quantized_vllm.py ← 用量化模型推理/服务
```

## 3. 各脚本快速参考

### 3.1 环境检测
```bash
python code/quantization/scripts/check_env.py
```
检查 PyTorch、transformers、量化库、CUDA 是否就绪。

### 3.2 bnb 动态量化对比(实验 1)
```bash
python code/quantization/apps/quantize_bnb.py
```
对比 FP16 / INT8 / NF4 在 LLaMA-3.2-1B 上的显存和速度。
**输出**:`logs/bnb_comparison_<时间戳>.md`

### 3.3 GPTQ 离线量化(实验 2)
```bash
python code/quantization/experiments/gptq_quantize.py
```
**核心实验**。用 130 条本地校准文本,4-bit 量化,保存到 `code/model/llama-3.2-1b-gptq-4bit/`。
**输出**:量化模型 + `logs/gptq_quantize_<时间戳>.md`

### 3.4 一键基准测试(实验 5)
```bash
bash code/quantization/scripts/run_all_benchmarks.sh
```
跑三个基准:
- `benchmarks/bench_throughput.py`:吞吐量 / 延迟 / TTFT
- `benchmarks/bench_memory.py`:磁盘 / 稳态显存 / 峰值显存
- `benchmarks/bench_quality.py`:困惑度 PPL / 输出对比

**输出**:`logs/bench_*.md`(3 个报告)

### 3.5 单独跑某个基准
```bash
# 只跑吞吐量,指定自定义 batch size
python code/quantization/benchmarks/bench_throughput.py \
    --fp16 /path/to/fp16 \
    --gptq /path/to/gptq \
    --batch-sizes 1 2 4 8 16

# 只测显存
python code/quantization/benchmarks/bench_memory.py \
    --fp16 /path/to/fp16 --gptq /path/to/gptq
```

### 3.6 量化模型推理(实验 6)
```bash
# 命令行聊天
python code/quantization/apps/serve_quantized_vllm.py chat

# 性能测试
python code/quantization/apps/serve_quantized_vllm.py bench

python code/quantization/apps/serve_quantized_vllm.py api --port 8000
```

### 3.7 自定义模型路径
所有脚本默认使用项目内本地模型。如需切换,设置环境变量:
```bash
export LLM_MODEL_PATH=/path/to/your/model
python code/quantization/apps/quantize_bnb.py
```

## 4. 关键参数说明

### 4.1 bnb 量化参数(在 `quantize_bnb.py` 中修改)
```python
BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",        # "nf4" 或 "fp4"
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True,   # 双重量化,再省 ~0.4 bits/param
)
```

### 4.2 GPTQ 量化参数(在 `gptq_quantize.py` 中修改)
```python
GPTQConfig(
    bits=4,                # 2/3/4/8
    group_size=128,        # 越小精度越高,但元数据更多。常见 32/64/128
    desc_act=False,        # True 精度更高但更慢
)
```

### 4.3 推理生成参数
所有脚本默认:
```python
max_new_tokens=128-256
do_sample=False           # 关闭采样,保证对比可复现
temperature=1.0
top_p=1.0
```

## 6. 常见问题排查

### 6.1 CUDA out of memory
- 关闭其他占显存的程序(`nvidia-smi` 看占用)
- 减少校准样本数(在 `gptq_quantize.py` 里把 `CALIBRATION_TEXTS` 切片)
- 用更小的 `batch_sizes` 跑基准

### 6.2 模型加载失败
- 检查路径是否存在:`ls code/model/llama-3.2-1b-gptq-4bit/`
- 看是否有 `config.json`、`model.safetensors`、`tokenizer.json`

### 6.3 速度比预期慢
- 确认 GPU 在用,不是 CPU 推理:`nvidia-smi` 应该看到 python 进程
- 检查 `device_map="auto"` 是否生效
- 量化模型的 kernel 是否 fallback 到慢路径(看日志里的 "fallback")

### 6.4 输出乱码
- 量化 bit 数太低(尝试 4-bit 而非 2-bit)
- group_size 太大(尝试 64 或 32)
- 校准数据不匹配任务类型
