# 技术总结:阶段 2 模型量化

## 三维对比总览

### 1. 吞吐量(tokens/s)

| 方案 | bs=1 | bs=4 | bs=8 | bs=8 vs FP16 |
|---|---|---|---|---|
| **FP16** baseline | 51.2 | 192.5 | **389.6** | 100% |
| bnb-INT8 | 10.8 | 33.3 | 61.1 | 15.7%(-6.4×) |
| bnb-NF4 | 19.9 | 83.6 | 169.7 | 43.6%(-2.3×) |
| **GPTQ-4bit** | 33.1 | 87.5 | **231.5** | 59.4%(-1.7×) |

**观察**:
- FP16 在所有 batch size 都最快(小模型上,反量化开销 > 节省)
- GPTQ 是量化方案中最快的(bs=8 时 231 tok/s,比 NF4 快 36%)
- bnb-INT8 在小模型上灾难性慢(LLM.int8 设计目标是 6B+ 模型)

### 2. 显存占用(GB)

| 方案 | 模型磁盘 | 加载后稳态 | 推理峰值 |
|---|---|---|---|
| FP16 | 4.61 | 3.63 | 2.32 |
| bnb-INT8 | 4.61 | 2.90 | 1.46 |
| bnb-NF4 | 4.61 | 2.35 | 1.03 |
| **GPTQ-4bit** | **0.98** | 2.43 | **1.01** |

**观察**:
- **GPTQ 磁盘仅 0.98 GB,压缩 4.72×** —— 这是静态量化的核心优势:模型文件本身被压缩
- bnb 的磁盘仍是 4.61 GB(因为加载的是 FP16 模型,运行时才转 INT8/NF4)
- 推理峰值显存:NF4 和 GPTQ 几乎一致(1.01-1.03 GB),都比 FP16 节省 56%
- bnb-INT8 推理峰值反而比 NF4 高 → LLM.int8 的混合精度元数据开销

### 3. 困惑度 PPL(越低越好)

| 方案 | PPL | vs FP16 |
|---|---|---|
| FP16 | 3.197 | baseline |
| bnb-INT8 | 3.148 | -1.53% ⚠️ |
| bnb-NF4 | 3.239 | +1.31% |
| GPTQ-4bit | 3.271 | **+2.29%** |

**观察**:
- GPTQ 4-bit 损失 2.29%,符合业界预期(4-bit 量化典型损失 1-3%)
- bnb-INT8 "PPL 更低"是**测量噪声**(测试文本只有 4 条,样本太小),不是真的更好
- 4-bit 量化在 1B 小模型上已经能保持 < 2.5% 困惑度损失

## 关键反直觉发现

### 发现 1:小模型上 INT8 比 FP16 慢 6.4×
- 原因:LLM.int8() 每次前向都要反量化 + bfloat16→FP16 cast,1B 模型计算太轻,反量化开销占比过大
- 启示:**动态量化的甜区是 6B+ 模型**,小模型应直接用 FP16 或 GPTQ

### 发现 2:静态量化(GPTQ)综合表现最优
- 速度:比 NF4 快 36%
- 显存:磁盘 4.72× 压缩(可分发)
- 精度:损失仅 2.29%
- **生产环境首选**

### 发现 3:Batch size 对吞吐量影响巨大
- FP16 bs=1 → bs=8:51 → 390 tok/s(7.6×)
- GPTQ bs=1 → bs=8:33 → 232 tok/s(7.0×)
- 启示:**LLM 推理是 memory-bound**,batch 越大越能摊销权重加载开销

## 量化方案选型矩阵

| 场景 | 推荐方案 | 理由 |
|---|---|---|
| 快速实验 / LoRA 微调 | bnb NF4 | 改 1 行代码即可,精度损失小 |
| 模型分发 / 部署 | GPTQ 4-bit | 模型文件压缩 4.72×,推理快 |
| 7B+ 模型 + 显存紧张 | GPTQ 4-bit | 静态量化在大模型上优势更明显 |
| 1B 以下小模型 | 直接 FP16 | 量化收益小,可能反而变慢 |
| CPU / 边缘设备 | GGUF + llama.cpp | 不在本阶段范围 |

## GPTQ 量化配置

```python
GPTQConfig(
    bits=4,
    group_size=128,    # 业界标准
    desc_act=False,    # 顺序量化(True 精度更高但慢)
    dataset=CALIB_TEXTS,  # 130 条中英文 + 代码混合
)
```

- 量化耗时:**4.64 分钟**(LLaMA-3.2-1B 在 RTX 3070 上)
- 量化时显存峰值:**3.97 GB**
- 产出模型:**0.98 GB**(原 FP16 4.61 GB,**压缩 4.72×**)

## 数值汇总

| 指标 | FP16 | GPTQ-4bit | 变化 |
|---|---|---|---|
| 模型磁盘 | 4.61 GB | 0.98 GB | **-78.7%(4.72× 压缩)** |
| 推理峰值显存 | 2.32 GB | 1.01 GB | -56.5% |
| bs=8 吞吐量 | 389.6 tok/s | 231.5 tok/s | -40.6% |
| 困惑度 | 3.197 | 3.271 | +2.29% |

**Trade-off**:用 2.29% 精度 + 40% 速度,换取 **4.72× 模型压缩** + **56% 显存节省**。
- 对于显存紧张或需要分发模型的场景,**这笔交易非常划算**
- 对于追求极致推理速度的场景,FP16 仍是最优
