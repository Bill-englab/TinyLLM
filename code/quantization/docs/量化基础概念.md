# 量化基础概念

> 本文是阶段 2 的理论底座。理解这些概念后,后面的代码不再是黑盒。

## 1. 什么是量化(Quantization)

**量化** = 把高精度的浮点数(通常是 FP16 / BF16)映射到低精度整数(INT8 / INT4),从而:

- 减少存储:INT8 比 FP16 小一半,INT4 小 4 倍
- 降低显存:同样模型能塞进更小的 GPU
- 加速推理:整数运算比浮点快,显存带宽是 LLM 推理的真正瓶颈

**关键认知**:LLM 推理是 **memory-bound**(显存带宽瓶颈),不是 compute-bound。所以模型小了 → 每次取权重快了 → 推理就快了。这就是量化的核心收益。

## 2. 数值范围:FP16 / INT8 / INT4

| 类型 | 比特数 | 表示范围 | 动态范围 |
|---|---|---|---|
| FP32 | 32 | ±3.4×10³⁸ | 大 |
| FP16 | 16 | ±65504 | 中 |
| BF16 | 16 | ±3.4×10³⁸ | 大(精度低) |
| INT8 | 8 | -128 ~ 127 | 256 个值 |
| INT4 | 4 | -8 ~ 7 | 16 个值 |
| NF4 | 4 | 16 个值(非均匀) | 信息论最优分布 |

LLM 权重通常是 FP16。量化到 INT4 意味着原来 65536 个可能值被压缩到只有 16 个 — 损失不可避免,关键是怎么把损失降到最低。

## 3. 量化的数学映射

### 3.1 对称量化(Symmetric)

```
q = round(x / scale)
scale = max(|x|) / 127        # INT8
```

零点对齐(0.0 ↔ 0),简单快速,但浪费了负数范围如果分布偏一侧。

### 3.2 非对称量化(Asymmetric)

```
q = round((x - zero_point) / scale)
scale = (max(x) - min(x)) / 255
zero_point = min(x)
```

能完整利用 [0, 255] 范围,精度更好,但计算时要补偿 zero_point。

### 3.3 LLM 实际选择

- **权重(Weight)**:通常用 **对称 + per-channel** —— 权重是确定的,离线算好就行
- **激活(Activation)**:通常用 **非对称 + per-tensor** —— 激活范围随输入变化

## 4. 粒度:per-tensor / per-channel / per-group

| 粒度 | 含义 | 精度 | 额外存储 |
|---|---|---|---|
| per-tensor | 整个张量一个 scale | 最低 | 1 个标量 |
| per-channel | 每个输出通道一个 scale | 高 | C 个标量 |
| per-group | 每 N 个连续值一个 scale(典型 N=128) | 最高 | (tensor_size / N) 个标量 |

**GPTQ 和 AWQ 都是 per-group(group_size=128)**,这是它们精度比朴素 per-channel 量化更高的关键。

## 5. 动态量化 vs 静态量化

### 5.1 动态量化(加载时量化)

代表:bitsandbytes INT8、NF4

- 加载 FP16 权重时,即时转换成 INT8/INT4 存储
- 推理时**反量化回 FP16** 再做矩阵乘法
- **不产出新模型文件**,每次加载都得重做
- 优点:零成本上手,改 1 行代码即可
- 缺点:不省加载时间,反量化在 GPU 上有开销

```python
# bitsandbytes 动态量化示例
model = AutoModelForCausalLM.from_pretrained(
    model_path,
    load_in_8bit=True,     # ← 一行搞定 INT8
    # load_in_4bit=True,   # ← 或 NF4
)
```

### 5.2 静态量化(离线量化,PTQ)

代表:GPTQ、AWQ

- **离线**用一批校准数据跑前向,统计每层权重和激活的分布
- 用统计结果求解最优 scale/zero_point,**永久写回新模型文件**
- 部署时直接加载量化模型,无需重做
- 优点:推理时无反量化开销,精度更高(考虑了激活分布)
- 缺点:量化过程耗时(1B 模型 3070 上 ~20 分钟),需要校准数据

```python
# GPTQ 离线量化示例(简化)
quantizer = GPTQQuantizer(bits=4, group_size=128, desc_act=False)
model = quantizer.quantize_model(model, calibration_data)
model.save_pretrained("./llama-3.2-1b-gptq-4bit")
```

### 5.3 一图看懂

```
┌─────────────────────────────────────────────────────────┐
│ 动态量化 (bnb)          静态量化 (GPTQ/AWQ)              │
├─────────────────────────────────────────────────────────┤
│ FP16 模型文件           FP16 模型文件                    │
│      │                        │                         │
│      ↓ 加载时                  ↓ 离线(一次性)           │
│   反量化层                校准 + 求解 scale              │
│      │                        │                         │
│      ↓ 推理                    ↓ 保存                   │
│   速度提升一般            INT4 模型文件(永久)          │
│                          │                              │
│                          ↓ 加载(秒级)                  │
│                          ↓ 推理                         │
│                          速度提升大                     │
└─────────────────────────────────────────────────────────┘
```

## 6. 校准(Calibration)是什么

静态量化必须做的步骤:

1. 选一批有代表性的输入(几百条文本)
2. 让原 FP16 模型跑前向
3. 记录每一层权重的统计 + 每一层激活值的范围
4. 用这些统计求解 scale / zero_point

**校准集选择原则**:
- 分布要接近真实推理场景
- 数量不必多(128~512 条通常够)
- GPTQ 论文用 C4 / WikiText,AWQ 用 WikiText

我们的实践:用 LLaMA-3 tokenizer 自带的少量中文+英文混合文本(避开网络问题)。

## 7. LLM 量化的核心挑战:Outlier Channels

LLM 有一个奇特现象:**少数通道的激活值会非常大**(比平均大 100 倍以上)。

朴素量化会被这些 outlier 拖累 —— 为了让 outlier 不溢出,scale 必须很大,导致其他正常通道的精度被压扁。

主流量化算法都是在解决这个问题的不同思路:

| 算法 | 思路 |
|---|---|
| **LLM.int8()** | outlier 通道保持 FP16,其余 INT8(混合精度) |
| **GPTQ** | 基于 Hessian 逆的逐层误差补偿,把量化误差"反向推"给未量化权重 |
| **AWQ** | 识别重要通道(salient),给它们更小的 scale 保护 |
| **SmoothQuant** | 把激活的 outlier "平滑"迁移到权重上 |

## 8. 主流量化方法对比表

| 方法 | 类型 | 精度 | 速度 | 工具链 | 适合场景 |
|---|---|---|---|---|---|
| bnb INT8 | 动态 | 中 | 中 | 简单 | 快速实验、LoRA 训练 |
| bnb NF4 | 动态 | 较高 | 中 | 简单 | QLoRA 训练 |
| GPTQ | 静态 | 高 | 快 | 成熟 | 部署、推理服务 |
| AWQ | 静态 | 最高 | 最快 | 较新 | 部署、对精度敏感 |
| GGUF | 静态 | 高 | 中 | llama.cpp 系 | CPU/边缘部署 |

> 本阶段覆盖前 4 种。GGUF 留到生产部署阶段。

## 9. 评估指标

量化做得好不好,要看三个维度:

### 9.1 显存
- 加载后 GPU 显存峰值
- 模型文件大小(磁盘占用)

### 9.2 速度
- 吞吐量(tokens/s)
- 首字延迟(TTFT)
- 每个请求平均延迟

### 9.3 精度
- **困惑度 PPL**(Perplexity):越低越好,衡量语言建模能力
- 下游任务评分(MMLU、CMMLU 等)
- 人工对比:固定 prompt,看输出是否仍合理

> 量化的 trade-off:**精度损失 1-3% 通常换 2-4× 速度提升和 4× 体积压缩**。

## 10. 常见误区

1. **"量化一定更快"** —— 不一定。bnb 动态量化的反量化有开销,小 batch 反而可能变慢
2. **"4-bit 比 8-bit 差很多"** —— 现代 4-bit(GPTQ/AWQ)精度损失往往 <2%,几乎不可感知
3. **"量化对所有模型效果一样"** —— 模型越大,量化越无损;小模型(1B 以下)更敏感
4. **"量化就是低精度推理"** —— 不,大多数方案激活仍是 FP16,只量化权重
