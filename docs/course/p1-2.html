1.2 内存层级:寄存器 → 共享内存 → L2 → HBM

理论 · 1.5h先修:1.1 产出:并入 gpu-体系结构笔记.md

1.1 讲说过:GPU 只怕"闲着等数据"。这一讲把"数据从哪来、有多慢"讲清楚。 结束后你会拿到一张3070 内存参数表——它就是 1.4 讲 roofline 的纵轴来源,也是本课程反复查询的"常数表"。

1. 一图看懂四级内存

   快 ←───────────────────────────────────────────→ 慢
   小 ←───────────────────────────────────────────→ 大

 [寄存器]      [共享内存 SMEM]      [L2 缓存]         [HBM 显存]
 每人手里草稿   教室里的白板          楼层储物柜         城市总仓库
 ~256KB/SM     ~128KB/SM(与L1分)   4MB 全卡共享       8GB 全卡共享
 ~TB/s 级      ~13-20 TB/s(片上)   ~2-3 TB/s          448 GB/s ← 瓶颈!
 延迟≈即时      延迟 ~30 周期        延迟 ~200 周期     延迟 ~400-600 周期

 距离核心:  同一周期可用  |  同一SM内    |   全卡    |   芯片外(GDDR6 颗粒)
全课程最重要的一张数字对比 计算引擎(FP16 Tensor ≈ 40 TFLOPS)与最慢一级内存(448 GB/s)之间差了 两个数量级。这意味着:只要数据要从 HBM 反复搬,小学生军团 大部分时间在等卡车。所有 GPU 优化的本质,都是减少"去总仓库的次数" 或"让卡车满载"。FlashAttention(第 4 篇)、PagedAttention(第 2 篇)、 量化(第 3 篇)——你回头看,全是这句话的具体化。

2. 各级内存的真实角色

寄存器:线程的私产

每个线程独占若干寄存器(3070 每间教室共 256KB,约 65536 个 32 位寄存器)。 编译器自动分配;kernel 里用的"局部变量"大多在这里。 寄存器不够用时会被"下放"到本地内存(实际走 L2/HBM),性能骤降 ——这就是 1.1 讲 occupancy 与寄存器互相挤压的原因。

共享内存:教室的白板(程序员可控的第一级)

同一 block(同一间教室)的所有线程共享,由程序员显式管理。 第 4 篇分块 matmul 的核心动作就是:先把一块数据从 HBM 抄到白板, 然后 128 个学生在白板上反复取用。Ampere 上 SMEM 与 L1 共享同一块 128KB 物理 SRAM,可配置切分。

L2:楼层储物柜(硬件自动)

全卡共享 4MB,硬件自动缓存。你能做的主要是利用 locality: 相邻 block 处理相邻数据时,后到的 block 能在 L2 命中。KV cache 的 PagedAttention 设计也吃 L2 的红利。

HBM(实为 GDDR6):城市总仓库

8GB @ 448 GB/s。注意消费卡的"HBM"是口误,3070 用的是 GDDR6 颗粒, 数据中心卡(H100)才是真 HBM(3 TB/s 级)。权重、KV cache、 激活全部住在这里——1.5 讲要算的"每 token 从这里读多少字节", 就是 decode 吞吐的总闸门。

3. 合并访存:让卡车满载

类比 warp 的 32 个学生各自报了一个地址要取货。
连续地址(如线程 i 取 array[i],共 32×4B=128B 连续): 卡车跑一趟全带回 → 1 次事务。
散乱地址(如 array[i*stride] 且 stride 很大): 32 趟卡车,每趟只运 4B → 带宽利用率 1/32。
"合并访存(coalescing)"= 把 32 个人的需求拼成一整卡车。 
// 好的模式:线程 i 读 a[i]          →  128B 连续,1 事务,带宽满载
// 坏的模式:线程 i 读 a[i*512]      →  每人隔 2KB,32 事务,利用率 ~3%
// 经典技巧:矩阵按 tile 分块读入 SMEM(第4篇实践),天然连续
坑:矩阵"按行处理"未必合并 行主序下,同一 warp 沿行方向取数是连续的(好); 沿列方向取数则步长=行宽(坏)。转置类的 kernel 性能差 往往就是这个原因。第 4 篇写 Triton 时会用 tile 化解决。

✅ 自测(面试向,点击揭晓)
1. 按延迟从小到大排序:寄存器、HBM、共享内存、L2
寄存器(即时)→ 共享内存(~30 周期)→ L2(~200 周期)→ HBM(~400-600 周期)。 面试常考的是量级与"差多少":SMEM 比 HBM 快一个数量级以上, 这就是分块(tiling)存在的理由。
2. 为什么说"所有 GPU 优化都是减少 HBM 访问或让其满载"?举两个例子
因为计算:带宽 ≈ 40T:448G,差两个数量级,kernel 时间通常由访存主导。 例子:①FlashAttention——分块到 SMEM,避免物化 N×N 注意力矩阵(减少 HBM 读写量); ②合并访存/tile 化——让每次 HBM 事务满载 128B(提高利用率)。 也可答量化(减少权重量→减少读字节)。
3. 什么是 bank conflict?
共享内存被切成 32 个 bank(可 32 路并行服务一个 warp)。 若 warp 内多个线程同时访问同一 bank 的不同地址,该 bank 内串行化, SMEM 性能成倍下降。经典解法:padding(加一列错开地址)。
