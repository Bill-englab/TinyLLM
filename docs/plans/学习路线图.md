### ✅ 第二阶段:模型量化(已完成)
**文件夹**: `code/quantization/`
**技术博客**: [03-模型量化篇](../03-模型量化篇.md)

**学习内容**:

**核心成果**:
- **GPTQ 4.72× 模型压缩**:4.61 GB → **0.98 GB**
- **推理峰值显存节省 56%**:2.32 GB → 1.01 GB
- **精度损失仅 2.29%**:PPL 3.197 → 3.271
- 9 个脚本 + 7 篇文档 + 1 个可直接复用的 GPTQ 量化模型
- 5 个真实工程问题与解决方案(NTFS/pip 镜像/auto-gptq 废弃/Marlin JIT/dataset 类型)

### 🔜 第三阶段:推理优化(进行中,计划已补充)
**文件夹**: `code/optimization/`(待创建)
**详细计划**: [stage-3-推理优化.md](./stage-3-推理优化.md)

> 2026-09-05 补充:原计划只有 4 项技术清单,重构为 6 模块。
> 核心变化:**测量先行**(3.0 是其余模块的验证工具)、
> **下钻原理**(kernel 层与引擎源码)、**7B 对比**(验证 1B 结论外推性)。

| 模块 | 主题 | 性质 |
|------|------|------|
| 3.0 | 测量与基础:GPU 体系结构 / HBM 带宽实测 / roofline / nsys profiling / 统一基准 harness(P99·重复·负载模型) | 🆕 新增,其余模块的地基 |
| 3.1 | KV Cache 深入:显存公式推导+实测 / vLLM block 管理 / KV INT8 量化 / prefix caching | 🆕 新增 |
| 3.2 | 量化×引擎:vLLM 加载 GPTQ / **7B GPTQ 对比**(验证 memory-bound 结论反转) / llama.cpp 对比(可选) | 强化(原计划) |
| 3.3 | 引擎内部:vLLM 源码精读(scheduler/block manager) / continuous batching 图解 / chunked prefill·PD 分离(概念) | 具体化(原"深入") |
| 3.4 | Kernel 层:Triton 入门 / FlashAttention 论文精读+原理复现 / torch.compile / CUDA Graphs | 🆕 新增 |
| 3.5 | 投机采样:1B draft + 3B GPTQ target 配对 / vLLM speculative decoding 实测 | 强化(原计划) |

**量化目标**: LLaMA-3.2-1B 有效吞吐 **1000+ tok/s**;
产出一个可运行的 7B GPTQ 推理服务与统一基准 harness。
