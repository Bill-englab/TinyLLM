## 一、课程说明(学生必读)

### 你将获得
1. 完整的 AI Infra 知识体系:硬件 → 推理 → 量化 → kernel → 训练 → 服务 → 分布式
2. 每个结论都有"为什么":roofline、显存公式、通信量推导,而不是背名词
3. 全部实践在本机完成:RTX 3070 8GB 上跑得通才算学会
4. 面试弹药:每讲自带高频自测题,结课有 30+ 题速查手册

### 学习节奏(每一讲的固定仪式)
```
📖 理论(30-60min) → 🔬 实践(60-120min,产出物入库) → ✅ 自测(面试题,能脱口而出) → ☑️ 勾选进度台
```
- 理论勾选标准:能向别人复述本讲要点
- 实践勾选标准:产出物(脚本/日志/笔记)已写入仓库对应目录
- 自测不通过就回到理论,直到能脱稿回答

### 第 1 篇 · GPU 体系结构与测量方法论(约 13.5h)★全课程地基

> **为什么先学这个**:后面每一篇的结论都靠本篇的工具验证。
> 学完后,"XX 优化为什么有效"将从道听途说变成你的推导。
> 代码目录:`code/optimization/fundamentals/` + `code/optimization/benchmarks/`

**1.1 GPU 计算模型**(理论 1.5h)
- 理论:SM(3070 有 46 个)/warp(32 线程)/grid-block-thread 层级;
  SIMT 执行与 warp 分歧;Tensor Core 与 FP16 矩阵累加;occupancy 概念
- 实践:用 torch 查询设备属性(SM 数、共享内存/SM);笔记画线程层级图
- 产出:`fundamentals/docs/gpu-体系结构笔记.md`(含 3070 规格表)
- 自测:①为什么 GPU 适合矩阵运算?②warp 分歧为什么会拖慢?

**1.2 内存层级**(理论 1.5h)
- 理论:寄存器(~TB/s)→ 共享内存(~20TB/s 片上)→ L2 → HBM(448GB/s);
  容量与带宽的三角关系;访存局部性;合并访存(coalescing)
- 实践:整理 3070 各级容量/带宽表(写入 1.1 的笔记)
- 自测:①各级内存延迟的数量级?②为什么 kernel 优化第一课是合并访存?

**1.3 实测你的 3070**(实践 2h)
- 理论:有效带宽 vs 标称带宽;矩阵乘算力测试方法
- 实践:大张量拷贝测带宽(预期 ≥350GB/s);fp16 matmul 测 TFLOPS;
  解释实测/标称差距
- 产出:`fundamentals/bench_bandwidth.py` + 日志
- 自测:①为什么有效带宽只有标称的 70-80%?②你的 roofline 两个顶点分别是多少?

**1.4 Roofline 模型**(理论 1.5h)
- 理论:算术强度 AI = FLOPs/Bytes;性能屋顶 = min(峰值算力, 带宽×AI);
  3070 的平衡点(用 1.3 实测值计算,约 45-90 FLOP/Byte);memory/compute bound 判定
- 实践:笔记推导 + 手绘 roofline 图
- 产出:`fundamentals/docs/roofline-推导.md`
- 自测:①给定 kernel 的 FLOPs 和字节数,如何判断 bound?②batch 增大对 AI 的影响?

**1.5 ★LLM decode 为什么 memory-bound**(核心 2h)
- 理论:decode 每 token 读全部权重(1B fp16 ≈ 2.5GB)→ 理论上限
  448/2.5 ≈ **180 tok/s**;GPTQ 后读量 ≈1.03 GB(词表 0.53 GB 压不动)→ 上限 ≈435 tok/s;
  为什么阶段 2 实测远低于此(kernel 效率、激活与非权重读、调度);
  为什么 batch 增大吞吐先升后饱和(权重读摊薄,AI 上升)
- 实践:把上述推导写成笔记,对照阶段 2 的 bench 数据逐项解释差距
- 产出:`fundamentals/docs/decode-memory-bound-推导.md`
- 自测:①★经典面试题:7B 模型 fp16 单卡 A100(2TB/s)decode 理论 tok/s?
  ②为什么小模型量化常常不提速,大模型却明显提速?

**1.6 Profiler 入门**(实践 2h)
- 理论:nsys 时间线(CPU/GPU/kernel/拷贝);torch profiler+kineto;
  注意:WSL2 下 ncu(计算级 profiling)不可用,时间线级可用(附录 A)
- 实践:profile Transformers 生成 100 token,导出时间线,找出时间大头 kernel
- 产出:`fundamentals/logs/nsys-初体验.md`(截图+解读)
- 自测:①时间线上"空隙"意味着什么?②如何从 profile 判断该优化访存还是计算?

**1.7 统一基准 harness**(实践 3h)★全课程共用工具
- 理论:TTFT(预填充)/TPOT(解码)指标定义;P50/P99;open vs closed loop;
  负载建模(prompt 长度分布、到达过程);重复次数与方差
- 实践:实现 `benchmarks/bench.py`(复用阶段 2 三件套的加载逻辑);
  用它复现阶段 1.5 的 349.6 tok/s 基线(±10%)
- 产出:`code/optimization/benchmarks/bench.py` + 使用说明
- 自测:①TTFT 和 TPOT 分别反映哪个阶段?②为什么基准必须报 P99 和方差?

### 第 2 篇 · 推理引擎核心机制(约 16h)★面试核心区

> 代码目录:`code/optimization/{kv_cache,engine_internals,speculative,quantized_serving}/`
> 前置操作:按附录 A 建 vLLM 独立 conda 环境

**2.1 prefill vs decode**(理论 1.5h)
- 理论:两阶段计算特征(prefill 一次算完→compute-bound;decode 逐 token→memory-bound);
  TTFT/TPOT 的归属;为什么两阶段对硬件的诉求矛盾(为 7.3 PD 分离埋伏笔)
- 实践:用 harness 测同一请求 prefill/decode 时间随输入长度的变化曲线
- 产出:`kv_cache/logs/prefill-decode-曲线.md`
- 自测:①为什么 prefill 是 compute-bound?②这个矛盾引出了什么架构?

**2.2 ★KV Cache**(核心 2.5h)
- 理论:自回归推理为什么需要缓存 K/V;显存公式
  `2 × layers × kv_heads × head_dim × bytes × seq`;
  代入本机模型(16 层/8 KV 头/head_dim 64,fp16 → **32KB/token**);
  GQA 如何把 KV 从 128KB 降到 32KB;8GB 显存的容量推算
- 实践:不同 seq_len/batch 下显存增量实测,与公式对齐(误差目标 <5%);
  推导"3070 上 1B 模型最多服务多少并发×上下文"
- 产出:`kv_cache/kv_cache_math.py` + 验证日志
- 自测:①★手算:7B(32 层/8 KV 头/128 维)fp16,4k 上下文单条 KV 多大?
  ②MQA/GQA/MLA 各是什么?

**2.3 Continuous Batching**(理论+实践 2h)
- 理论:static batching 的尾部等待浪费;iteration 级调度;
  vLLM scheduler 的核心循环;max_num_seqs 的意义
- 实践:不同 max_num_seqs(1/2/4/8/16)的吞吐曲线(用 harness)
- 产出:`engine_internals/logs/cb-吞吐曲线.md`
- 自测:①CB 为什么提升 GPU 利用率?②和 CPU 的批处理调度有何异同?

**2.4 ★PagedAttention**(核心 3h)
- 理论:论文精读;OS 虚拟内存借鉴:逻辑块/物理块/block table;
  消除内部碎片与预预留浪费;代价(块表间接寻址);
  vLLM 源码走读:`vllm/core/scheduler.py` + block manager
- 实践:源码走读笔记(一次 generate 的调用链图);开启 block 用量日志观测
- 产出:`engine_internals/docs/vllm-源码走读.md`(调用链图)
- 自测:①PagedAttention 借鉴了操作系统什么机制?解决了什么浪费?
  ②block_size 大小的取舍?

**2.5 Prefix Caching 与 Chunked Prefill**(理论+实践 2h)
- 理论:前缀复用(多轮对话/system prompt 场景);block 命中逻辑;
  chunked prefill:切长 prefill 避免阻塞 decode(TTFT/TPOT 再平衡)
- 实践:共享 1k system prompt 的两组请求,开/关 prefix caching 的 TTFT 对比
- 产出:`kv_cache/logs/prefix-caching-对比.md`
- 自测:①prefix caching 的命中条件?②chunked prefill 缓解什么问题?

**2.6 投机采样**(实践 3h)
- 理论:draft 逐 token 预测 + target 并行验证;acceptance rate;
  理论加速上界;输出分布与收益的关系
- 实践:vLLM speculative decoding,1B draft + 3B GPTQ target;
  测 acceptance rate 与端到端加速比;分析低于多少 acceptance 反而变慢
- 产出:`speculative/logs/投机采样-实验.md`
- 自测:①投机采样为什么输出分布不变?②★acceptance 多少才划算(推导期望)?
