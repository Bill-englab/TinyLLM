# Design: build-course-portal-p1

## Context

用户确认学习循环:备课(我)→ 自学(学生,材料+实践)→ 答疑(对话)→
沉淀(我起草博客,学生审)。课程制三件套已就绪,缺"教材"环节。

## Goals / Non-Goals

**Goals:** 课件站双击可用;与 dashboard 进度互通;第 0/1 篇完整课件;
学习循环协议成文;滚动备课机制明确。
**Non-Goals:** 不做服务端/账号/视频;不一次性备完 47 讲(质量优先,
后面课件吸收前面学习反馈);不自动化博客(学生学完触发,人工起草)。

## Decisions

### Decision 1: 静态多页 + 共享 CSS/JS,file:// 直开

file:// 下 <link>/<script> 相对路径可加载(无 CORS 限制),仅 fetch 受限,
故内容直接写在各页 HTML 中;共享 style.css/course.js 抽公共样式与逻辑。
比单文件巨页更易维护,比 SSG(需构建)更符合"双击即用"。

### Decision 2: 复用 dashboard 的 localStorage 键(tinyllm-course-v1)

课件页勾选 = dashboard 勾选,同一数据结构 {id:{t,p}},零转换。
代价:换浏览器进度不共享——沿用既有约定(导出快照迁移)。

### Decision 3: 自测用原生 <details> 揭晓,零 JS 依赖

交互最少化:答案揭晓用 <details>/<summary>;仅完成勾选需要 JS。

### Decision 4: 滚动备课,一次一篇

47 讲一次性产出会稀释质量,且第 2 篇起应吸收第 1 篇学习中的问题反馈。
节奏:学生开始学第 N 篇时,我准备第 N+1 篇课件;门户标注各篇课件状态。
第 0 篇(复习)与第 1 篇(地基)本次一并产出,学生可立即开学。

### Decision 5: 课件是"教材",博客仍是"沉淀"

课件用第二人称教学口吻,含类比与推导;博客保持既有第一人称学习记录
风格,数据来自学生实验——两者不重复:课件讲"是什么为什么",
博客记"我做了什么、踩了什么坑"。
