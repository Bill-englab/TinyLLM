# 阶段整理技能

本技能规范AI推理优化学习的完整学习流程，确保每个学习阶段都有清晰的开始和结束，并产出结构化的学习成果。

## 学习流程概览

AI推理优化学习采用双阶段循环模式：

### 第一阶段：对话式学习
- **触发条件**：开始新的学习主题或阶段
- **工作方式**：用户通过对话提出需求和想法，助手实时创建代码、实验demo
- **交互特点**：一边聊天一边开发，实时反馈和调整
- **输出成果**：可运行的代码、实验结果、技术讨论记录

### 第二阶段：阶段整理
- **触发条件**：达成阶段性学习目标后
- **整理内容**：系统化整理学习成果，形成可复用的知识资产
- **输出成果**：技术博客、代码目录、文档体系、学习记录

---

## 第一阶段：对话式学习

### 触发条件
当用户表示要开始新的学习主题、技术概念或实践时，进入此阶段。

### 工作流程

#### 1. 需求理解与规划
- 明确当前学习主题和目标
- 评估硬件环境和时间投入
- 设定阶段性验证点

#### 2. 代码创建与实验
- 根据用户需求实时创建代码
- 创建可运行的实验demo
- 通过对话调整实现方案

#### 3. 技术验证
- 运行实验验证代码功能
- 收集性能数据和运行结果
- 记录技术细节和问题

#### 4. 迭代优化
- 根据实验结果调整方案
- 修复遇到的技术问题
- 优化代码质量和性能

### 输出管理
在对话式学习阶段，创建的文件应临时保存在适当位置：
- 代码文件：`code/temp/` 或 `code/当前阶段名称/`
- 实验结果：保存日志、截图、性能数据
- 技术讨论：重要决策和发现记录

## 第二阶段：阶段整理

### 触发条件
当用户表示：
- "这个阶段完成了" 或 "这个内容学会了"
- "我们来整理一下"
- "写一篇博客总结一下"
- "把这些代码整理一下"

或达成以下任一条件：
- 完成了阶段性的学习目标
- 解决了主要技术问题
- 创建了可演示的成果
- 需要进入下一学习阶段

### 标准化整理步骤

#### 步骤1：技术博客撰写

**博客结构模板**：
1. 引言与背景（学习动机、目标设定、环境准备）
2. 学习过程（核心步骤、关键技术点、代码示例）
3. 问题解决（遇到的问题、排查过程、解决方案）
4. 技术细节（核心代码、配置说明、参数调优）
5. 效果展示（性能数据、运行效果、用户体验）
6. 总结与展望（学习成果、经验教训、下一步计划）

**撰写指导**：
- 使用第一人称，增加真实感
- 详细描述问题解决过程
- 包含核心代码片段（保持简洁）
- 提供性能数据和实际效果
- 适合技术人员阅读的语言风格

**博客位置**：`docs/` 目录下，命名如 `XX阶段-技术总结.md`

#### 步骤2：目录结构创建

**在 `code/` 下创建阶段目录**：
```
code/
├── 当前阶段名称/
│   ├── apps/           # 应用程序
│   ├── experiments/   # 实验代码
│   ├── scripts/        # 工具脚本
│   ├── tests/         # 测试文件
│   └── docs/          # 技术文档
```

**目录命名规范**：
- 使用英文小写和下划线：`model_deployment/`, `quantization/`, `optimization/`
- 避免中文目录名
- 保持命名一致性

#### 步骤3：代码整理与归档

**代码整理流程**：

1. **筛选核心代码**：
   - 识别最终稳定版本的代码
   - 移除实验性和临时代码
   - 确保代码质量和可读性

2. **分类存放代码**：
   - 应用代码 → `apps/`
   - 实验代码 → `experiments/`
   - 工具脚本 → `scripts/`
   - 测试代码 → `tests/`

3. **代码规范化**：
   - 添加必要的注释
   - 统一代码风格
   - 确保代码可运行

4. **归档临时文件**：
   - 将中间实验代码移至 `archive/`
   - 保留有价值的中间版本
   - 删除无用的临时文件

#### 步骤4：文档体系建立

**创建以下文档**：

1. **README.md** - 阶段总体说明
2. **使用指南.md** - 详细使用方法
3. **技术总结.md** - 学习成果总结
4. **代码说明.md** - 代码结构和说明
5. **问题记录.md** - 遇到的问题和解决方案

**文档位置**：阶段目录下的 `docs/` 子目录

#### 步骤5：学习记录形成

**学习记录内容**：

1. **学习目标**：本阶段的学习目标
2. **技术栈**：使用的技术和工具
3. **时间投入**：学习时长和阶段划分
4. **关键决策**：重要的技术选择和理由
5. **问题解决**：主要问题和解决方案
6. **成果清单**：完成的具体内容
7. **经验教训**：收获的经验和遇到的坑

**记录格式**：
```markdown
# 阶段名称学习记录

## 学习目标
- 目标1
- 目标2

## 技术栈
- 技术1
- 技术2

## 时间投入
- 总时长：X小时
- 阶段划分：...

## 关键决策
- 决策1：...
- 决策2：...

## 问题解决
- 问题1：解决方案...
- 问题2：解决方案...

## 成果清单
- 成果1
- 成果2

## 经验教训
- 经验1
- 经验2
```

#### 步骤6：代码仓整理

**清理主目录**：
- 移除零散的临时文件
- 清理重复的代码文件
- 保持项目结构清晰

**更新主文档**：
- 更新根目录 `README.md`
- 更新学习路线图
- 更新项目结构说明

**版本管理建议**：
- 提交当前阶段成果到版本控制
- 创建阶段标签
- 编写commit message

## 阶段边界与触发条件

### 第一阶段 → 第二阶段
**触发条件**：
- 用户明确表示完成当前阶段
- 达成了预设的学习目标
- 创建了稳定可用的成果
- 准备进入下一学习主题

**拒绝整理的情况**：
- 还在实验阶段，成果不稳定
- 遇到技术问题需要继续解决
- 用户表示继续当前主题学习

### 第二阶段 → 第一阶段（新阶段开始）
**触发条件**：
- 完成了当前阶段的整理
- 用户提出新的学习主题
- 准备开始新的学习周期

## 技术博客撰写指南

### 博客风格定位
- **平台**：知乎、技术博客
- **读者**：有基础技术经验但缺乏AI推理经验的开发者
- **风格**：技术实操型，详细真实的问题解决过程
- **长度**：8000-10000字

### 内容结构模板

#### 第一章：引言与项目背景（10-15%）
- 为什么选择这个主题
- 个人学习动机
- 硬件环境介绍
- 预期成果设定

#### 第二章：学习过程（20-25%）
- 环境准备详细过程
- 核心技术概念学习
- 代码创建和实验过程
- 迭代优化过程

#### 第三章：问题解决（20%）
- 遇到的主要技术问题
- 问题排查和解决过程
- 关键技术决策和理由
- 成功和失败的经验

#### 第四章：技术细节（25-30%）
- 核心代码示例和解析
- 关键技术点详解
- 性能优化考虑
- 最佳实践总结

#### 第五章：效果展示（10-15%）
- 性能数据和基准测试
- 用户体验描述
- 实际运行效果
- 与其他方案的对比

#### 第六章：总结与展望（5-10%）
- 学习成果总结
- 经验教训和心得
- 下一步学习计划
- 给读者的建议

### 代码示例原则
- **展示核心片段**：只展示关键代码，保持简洁
- **详细注释**：每个代码片段都有详细说明
- **可运行性**：确保代码可以直接运行
- **避免冗长**：避免展示过于复杂的代码块

## 代码整理规范

### 代码筛选标准
- **保留**：最终稳定版本、核心功能代码、重要实验代码
- **归档**：中间版本、实验性代码、调试代码
- **删除**：完全失败的尝试、重复代码、无用文件

### 代码分类规则
- **apps/****：可直接运行的应用程序
- **experiments/****：实验性代码，可能有多个版本
- **scripts/****：工具脚本和自动化代码
- **tests/****：测试代码和验证脚本

### 代码质量要求
- **可运行性**：确保代码可以正常执行
- **可读性**：添加必要的注释和文档
- **可维护性**：代码结构清晰，便于后续修改
- **性能考虑**：关键路径的性能优化

- **阶段划分**：
  - 环境准备：X小时
  - 代码开发：X小时

## 关键决策
- **决策1**：选择LLaMA-3.2-1B-Instruct
  - 理由：8GB显存的最佳选择
  - 替代方案：LLaMA-3.2-3B（显存不足）
- **决策2**：使用Gradio ChatInterface
  - 理由：解决多轮对话问题
  - 替代方案：Gradio Blocks（兼容性问题）

### 问题1：中文输出乱码
- **现象**：模型中文输出显示乱码
- **原因**：Windows默认编码不是UTF-8
- **解决方案**：设置UTF-8编码输出
- **经验**：编码问题是常见但容易被忽略的问题

### 问题2：多轮对话格式问题
- **现象**：`too many values to unpack (expected 2)`
- **原因**：Gradio历史记录格式处理不当
- **解决方案**：增加类型检查和格式验证
- **经验**：历史记录格式需要仔细研究文档
