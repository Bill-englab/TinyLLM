# 阶段整理技能

本技能规范AI推理优化学习的完整流程，确保每个学习阶段都有清晰的开始和结束，并产出结构化的学习成果。

## 学习流程概览

AI推理优化学习采用双阶段循环模式：

### 第一阶段：对话式学习
- **触发条件**：用户表示要开始新的学习主题或阶段
- **工作方式**：用户通过对话提出需求，助手实时创建代码、实验demo
- **输出管理**：代码文件临时保存在 `code/temp/` 或 `code/当前阶段名称/`

### 第二阶段：阶段整理
- **触发条件**：用户表示"这个阶段完成了"、"整理一下"、"写一篇博客总结一下"
- **整理内容**：系统化整理学习成果，形成可复用的知识资产

**拒绝整理的情况**：成果不稳定、技术问题未解决、用户表示继续当前主题学习

## 阶段整理标准化步骤

当触发阶段整理时，按顺序执行以下6个步骤：

### 步骤1：技术博客撰写

**位置**：`docs/XX阶段-技术总结.md`（如 `docs/03-模型量化篇.md`）

**博客结构**：
1. 引言与背景（学习动机、目标设定、环境准备）
2. 学习过程（核心步骤、关键技术点、代码示例）
3. 问题解决（遇到的问题、排查过程、解决方案）
4. 技术细节（核心代码、配置说明、参数调优）
5. 效果展示（性能数据、运行效果、用户体验）
6. 总结与展望（学习成果、经验教训、下一步计划）

**撰写要求**：
- 使用第一人称，增加真实感
- 详细描述问题解决过程
- 包含核心代码片段（保持简洁）
- 提供性能数据和实际效果
- 长度：8000-10000字

详见 [references/blog-guide.md](references/blog-guide.md)

### 步骤2：目录结构创建

在 `code/` 下创建阶段目录：

```
code/阶段名称/
├── apps/           # 应用程序（可直接运行）
├── experiments/    # 实验代码（可能有多个版本）
├── scripts/        # 工具脚本
├── tests/          # 测试文件
├── docs/           # 技术文档
├── archive/        # 归档文件
└── 学习记录.md
```

**命名规范**：英文小写+下划线（如 `model_deployment/`），避免中文目录名

详见 [references/directory-structure.md](references/directory-structure.md)

### 步骤3：代码整理与归档

1. **筛选核心代码**：识别最终稳定版本，移除实验性和临时代码
2. **分类存放**：
   - 应用代码 → `apps/`
   - 实验代码 → `experiments/`
   - 工具脚本 → `scripts/`
   - 测试代码 → `tests/`
3. **代码规范化**：添加必要注释，统一代码风格，确保可运行
4. **归档临时文件**：中间实验代码移至 `archive/`，删除无用文件

### 步骤4：文档体系建立

在阶段目录的 `docs/` 下创建：

| 文档 | 内容 |
|------|------|
| README.md | 阶段总体说明、快速开始指南 |
| 使用指南.md | 详细使用方法、环境配置、常见问题 |
| 技术总结.md | 学习成果总结、性能数据汇总 |
| 代码说明.md | 代码结构说明、主要模块介绍 |
| 问题记录.md | 遇到的问题列表、排查和解决过程 |

### 步骤5：学习记录形成

在阶段目录根目录创建 `学习记录.md`，包含：
- 学习目标、技术栈、时间投入
- 关键决策（技术选择和理由）
- 问题解决（现象、原因、解决方案、经验）
- 成果清单、经验教训

详见 [references/learning-record-template.md](references/learning-record-template.md)

### 步骤6：代码仓整理

1. **清理主目录**：移除零散临时文件，清理重复代码
2. **更新主文档**：
   - 更新根目录 `README.md`
   - 更新 `docs/plans/学习路线图.md`(计划层)与 `docs/progress/PROGRESS.md`(进度层)
   - 更新 `项目结构说明.md` 与 `docs/INDEX.md`(索引同步)
3. **版本管理建议**：提交当前阶段成果，创建阶段标签
