# 目录结构规范

## 根目录结构
```
LLM_Project/
├── README.md                    # 项目总体说明
├── 快速入门.md                  # 快速启动指南
├── 项目结构说明.md              # 结构文档
├── code/                       # 所有代码和模型
│   ├── 阶段1_名称/              # 第1阶段代码
│   ├── 阶段2_名称/              # 第2阶段代码
│   ├── model/                   # 模型文件
│   └── 学习路线图.md
└── docs/                       # 所有文档
    ├── 01-模型部署篇.md      # 第1阶段博客
    ├── 02-模型量化篇.md      # 第2阶段博客
    └── ...
```

## 阶段目录结构
```
code/阶段名称/
├── apps/                      # 应用程序（可直接运行）
├── experiments/               # 实验代码（可能有多个版本）
├── scripts/                   # 工具脚本和自动化代码
├── tests/                     # 测试代码和验证脚本
├── docs/                      # 技术文档
│   ├── README.md              # 阶段总体说明
│   ├── 使用指南.md            # 详细使用方法
│   ├── 技术总结.md            # 学习成果总结
│   ├── 代码说明.md            # 代码结构和说明
│   └── 问题记录.md            # 遇到的问题和解决方案
├── archive/                   # 归档文件（中间版本、实验代码）
└── 学习记录.md                # 本阶段学习记录
```

## 目录命名规范
- 使用英文小写和下划线：`model_deployment/`, `quantization/`, `optimization/`
- 避免中文目录名
- 保持命名一致性

## 代码分类规则
- **apps/**：可直接运行的应用程序
- **experiments/**：实验性代码，可能有多个版本
- **scripts/**：工具脚本和自动化代码
- **tests/**：测试代码和验证脚本

## 代码筛选标准
- **保留**：最终稳定版本、核心功能代码、重要实验代码
- **归档**：中间版本、实验性代码、调试代码 → 移至 `archive/`
- **删除**：完全失败的尝试、重复代码、无用文件

## 代码质量要求
- **可运行性**：确保代码可以正常执行
- **可读性**：添加必要的注释和文档
- **可维护性**：代码结构清晰，便于后续修改
- **性能考虑**：关键路径的性能优化
